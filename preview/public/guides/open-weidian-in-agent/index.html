Open a Weidian link in your preferred agent

Store the marketplace URL once. Choose Superbuy, Sugargoo, Kakobuy, or another agent when you buy—not when you save.

Problem

Agent links go stale

Agents change URL schemes and drop platforms. If every row in your sheet is a Fansbuy-only wrap, a platform change breaks the list.

Pattern

Canonical store, agent at click

  • Item stores the canonical marketplace URL.
  • You pick a preferred agent (and can change it without rewriting the shelf).
  • Buy opens the agent with that URL. Optional: open original Weidian/Yupoo.
  • Affiliate or referral params attach only on outbound Buy when the agent pays referral—not into stored data.
The three link shapes

Agents do not all want the same thing

This is why a stored agent link is fragile. The agents split into three groups, and a link built for one group means nothing to another.

  • Wrap the whole URL. Superbuy, Sugargoo, Kakobuy and AllChinaBuy take the marketplace URL as a query parameter.
  • Want the item id. CNFans, Hoobuy, Oopbuy and Mulebuy take the numeric id plus their own name for the platform. The URL itself is discarded.
  • Want both. Fansbuy puts the id in the path and the URL in a parameter, and only for Weidian.

Convert a shelf from group one to group two and you cannot do it by find-and-replace. You need the id, which is inside the original link you overwrote.

Where the id lives

Each marketplace hides it somewhere else

  • Weidian — itemID in the query string.
  • Taobao and Tmall — id in the query string.
  • 1688 — the number in /offer/<id>.html, or offerId.

Credenza reads the id at Buy time, from the canonical link it kept. You never copy a number by hand.

When it cannot wrap

The link still opens

Three cases fail: the agent does not serve that marketplace, the id is not in the URL, or the link is a Yupoo album, which is a photo page and not an item.

In every case Buy opens the original link untouched. A haul planner that returned a dead end on an unsupported link would be worse than a plain bookmark, so it never does that.

Switching agents

A one-field change, not a migration

Your agent choice is a setting, not a property of each item. Change it once and every Buy button on the shelf points somewhere new. Nothing stored changes, so switching back costs the same nothing.

Compare the agents themselves in which agent should I use.

What Credenza is not

No in-app checkout

Purchases complete on the agent site. Credenza is the decision layer before that click.

Some Buy links carry a referral code, which is how a free planner pays for the AI it runs. The code attaches to the outbound click only. It is never written into your stored link, and it never changes which agent you see.

Credenza is a decision layer, not a marketplace and not a W2C search engine. You bring the links from communities and stores you already use.
